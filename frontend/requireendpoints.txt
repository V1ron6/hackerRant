========================================================
  REQUIRED API ENDPOINTS — HGBMI Church Attendance
========================================================

================================================================
SECTION A: Endpoints Used in Frontend but MISSING from API Docs
================================================================

1. POST /admin/messages/send
   Used in: sendMessage.jsx
   Purpose: Broadcast messages/notifications to all members, a specific cell, or an individual member
   Expected Body: { subject, body, audience, cellName?, memberId? }
   Expected Response: { success: true, data: { messageId, recipientCount } }

2. POST /auth/logout
   Used in: adminDashboard.jsx, cellleaddashboard.jsx, usherdashboard.jsx, userDashboard.jsx
   Purpose: Invalidate the JWT session on the server side
   Expected Headers: Authorization: Bearer <token>
   Expected Response: { success: true, message: "Logged out successfully" }

3. PUT /auth/update-profile
   Used in: usherprofile.jsx, userProfile.jsx
   Purpose: Update the logged-in user's name, phone number, or password
   Expected Body (profile): { firstName, lastName, phoneNumber }
   Expected Body (password): { currentPassword, newPassword }
   Expected Response: { success: true, data: { ...updatedUser } }
   Note: Docs have "PUT /auth/profile" — either align the docs or the code

4. GET /auth/me
   Used in: usherprofile.jsx, userProfile.jsx, userDashboard.jsx
   Purpose: Fetch the currently logged-in user's full profile
   Expected Response: { success: true, data: { id, firstName, lastName, email, phoneNumber, role, cellName, isVerified, createdAt } }
   Note: Docs have "GET /auth/profile" — either align the docs or the code

5. GET /auth/qrcode
   Used in: userDashboard.jsx
   Purpose: Retrieve the member's unique QR code image or data string
   Expected Response: { success: true, data: { qrCode: "<base64 or URL>" } }
   Note: Docs mention QR code in verify-email response but there is no dedicated GET endpoint documented


================================================================
SECTION B: Suggested New Analytics Endpoints
================================================================

6. GET /attendance/analytics/growth
   Purpose: Track member registration/growth over time
   Use case: Growth tracker charts on cell lead & admin dashboards
   Query Params:
     - period (optional): "weekly" | "monthly" (default: "weekly")
     - cellName (optional): Filter by cell (superAdmin only)
     - startDate (optional): YYYY-MM-DD
     - endDate (optional): YYYY-MM-DD
   Expected Response:
     {
       "success": true,
       "data": [
         { "date": "2026-02-01", "newMembers": 5, "totalMembers": 120 },
         { "date": "2026-02-08", "newMembers": 3, "totalMembers": 123 }
       ]
     }

7. GET /attendance/analytics/retention
   Purpose: Calculate member retention/engagement rate
   Use case: Analytics pages — shows how many members are actively attending vs dropping off
   Query Params:
     - weeks (optional): Number of weeks to analyze (default: 4)
     - cellName (optional): Filter by cell
   Expected Response:
     {
       "success": true,
       "data": {
         "retentionRate": "78.50",
         "activeMembers": 118,
         "inactiveMembers": 32,
         "atRiskMembers": 15,
         "totalMembers": 150,
         "period": "4 weeks"
       }
     }

8. GET /attendance/analytics/trends/service
   Purpose: Per-service-type attendance trend over time (not just totals)
   Use case: Line/bar chart comparing attendance across service types over weeks
   Query Params:
     - period (optional): Number of days (default: 30)
     - serviceTypeId (optional): Filter to single service type
   Expected Response:
     {
       "success": true,
       "data": [
         { "date": "2026-02-01", "serviceType": "sunday_service", "serviceName": "Sunday Service", "count": 42 },
         { "date": "2026-02-01", "serviceType": "cell_meeting", "serviceName": "Cell Meeting", "count": 28 },
         { "date": "2026-02-08", "serviceType": "sunday_service", "serviceName": "Sunday Service", "count": 48 }
       ]
     }

9. GET /attendance/analytics/trends/cell
   Purpose: Per-cell attendance trend over time
   Use case: Cell comparison chart in admin analytics — see which cells are growing/declining
   Query Params:
     - period (optional): Number of days (default: 30)
     - cellName (optional): Filter to single cell
   Expected Response:
     {
       "success": true,
       "data": [
         { "date": "2026-02-01", "cellName": "Light Fellowship", "count": 25 },
         { "date": "2026-02-01", "cellName": "Spirit Fellowship", "count": 20 },
         { "date": "2026-02-08", "cellName": "Light Fellowship", "count": 28 }
       ]
     }

10. GET /attendance/analytics/first-timers
    Purpose: Identify members who attended for the first time in a given date range
    Use case: New visitor tracking, outreach and follow-up workflows
    Query Params:
      - startDate (required): YYYY-MM-DD
      - endDate (required): YYYY-MM-DD
      - cellName (optional): Filter by cell
    Expected Response:
      {
        "success": true,
        "data": [
          {
            "memberId": "uuid",
            "firstName": "Sarah",
            "lastName": "Mensah",
            "email": "sarah@example.com",
            "cellName": "Light Fellowship",
            "firstAttendanceDate": "2026-02-15",
            "serviceType": "Sunday Service"
          }
        ]
      }

11. GET /attendance/analytics/streaks
    Purpose: Track consecutive-week attendance streaks per member
    Use case: Engagement gamification, member recognition, consistency awards
    Query Params:
      - cellName (optional): Filter by cell
      - minStreak (optional): Minimum streak length to include (default: 2)
    Expected Response:
      {
        "success": true,
        "data": [
          {
            "memberId": "uuid",
            "firstName": "John",
            "lastName": "Doe",
            "cellName": "Light Fellowship",
            "currentStreak": 8,
            "longestStreak": 12,
            "lastAttendance": "2026-03-01"
          }
        ]
      }

12. GET /attendance/analytics/peak-times
    Purpose: Analyze check-in time distribution (for heatmap or histogram)
    Use case: Understand when members typically arrive, optimize service scheduling
    Query Params:
      - period (optional): Number of days (default: 30)
      - serviceTypeId (optional): Filter by service type
    Expected Response:
      {
        "success": true,
        "data": [
          { "hour": 7, "count": 5 },
          { "hour": 8, "count": 25 },
          { "hour": 9, "count": 48 },
          { "hour": 10, "count": 30 },
          { "hour": 11, "count": 12 }
        ]
      }

13. GET /attendance/compare/periods
    Purpose: Compare two arbitrary date ranges side by side
    Use case: "This month vs last month" comparison widget on dashboards
    Query Params:
      - period1Start (required): YYYY-MM-DD
      - period1End (required): YYYY-MM-DD
      - period2Start (required): YYYY-MM-DD
      - period2End (required): YYYY-MM-DD
      - cellName (optional): Filter by cell
    Expected Response:
      {
        "success": true,
        "data": {
          "period1": { "label": "Feb 2026", "totalAttendance": 420, "avgPerDay": 30, "rate": "75.00" },
          "period2": { "label": "Jan 2026", "totalAttendance": 380, "avgPerDay": 27, "rate": "68.50" },
          "delta": { "attendance": 40, "rate": "+6.50", "direction": "up" }
        }
      }

14. GET /admin/dashboard/summary
    Purpose: Single lightweight endpoint returning all dashboard stats
    Use case: Reduces 3-4 separate API calls on dashboard load to just 1
    Expected Response:
      {
        "success": true,
        "data": {
          "totalMembers": 150,
          "activeMembers": 135,
          "totalCells": 5,
          "totalPrivilegedUsers": 8,
          "todayAttendance": 45,
          "todayTotal": 150,
          "todayRate": "30.00",
          "last30DaysAttendance": 1250,
          "last30DaysRate": "72.50",
          "newMembersThisMonth": 12
        }
      }

15. GET /attendance/absentees/chronic
    Purpose: Identify members who have missed N or more consecutive services
    Use case: Pastoral care follow-up, "at-risk" member lists, re-engagement campaigns
    Query Params:
      - minMissed (optional): Minimum consecutive missed services (default: 3)
      - cellName (optional): Filter by cell
    Expected Response:
      {
        "success": true,
        "data": [
          {
            "memberId": "uuid",
            "firstName": "Peter",
            "lastName": "Williams",
            "email": "peter@example.com",
            "phoneNumber": "+233201234571",
            "cellName": "Spirit Fellowship",
            "consecutiveMissed": 5,
            "lastSeenDate": "2026-01-25",
            "lastServiceType": "Sunday Service"
          }
        ]
      }
